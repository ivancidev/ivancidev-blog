## ¿Qué es el App Router?

Next.js 14 introdujo el **App Router** como el nuevo estándar para estructurar aplicaciones. A diferencia del Pages Router, el App Router usa el directorio `/app` y trae consigo Server Components por defecto.

La diferencia más importante es el modelo mental: en el App Router, **el servidor es el punto de partida**, no el cliente.

### Server Components vs Client Components

Por defecto, todos los componentes en el App Router son **Server Components**. Esto significa que se renderizan en el servidor y no incluyen JavaScript en el cliente.

```tsx
// Server Component (por defecto) — no envía JS al browser
async function PostList() {
  const posts = await db.posts.findAll(); // Se ejecuta en servidor
  return <ul>{posts.map(p => <li key={p.id}>{p.title}</li>)}</ul>;
}
```

Para usar hooks o interactividad, necesitas añadir `"use client"` al inicio del archivo:

```tsx
"use client";
import { useState } from "react";

export function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(c => c + 1)}>{count}</button>;
}
```

La regla es simple: si no necesita interactividad, déjalo como Server Component.

### Layouts anidados

Una de las mejores características del App Router son los **layouts anidados**. Puedes tener un layout para toda la app y layouts específicos para cada sección sin repetir código:

```
app/
  layout.tsx      → Layout raíz (navbar, footer)
  page.tsx        → Página home
  blog/
    layout.tsx    → Layout específico del blog
    page.tsx      → Lista de posts
    [slug]/
      page.tsx    → Post individual
```

Cada `layout.tsx` recibe `{children}` y los envuelve automáticamente. Si navegas de `/blog` a `/blog/mi-post`, el layout del blog **no se vuelve a montar** — solo cambia el contenido interno.

### Data fetching simplificado

Olvídate de `getStaticProps` y `getServerSideProps`. Ahora solo necesitas `async/await` directamente en el componente:

```tsx
// app/blog/page.tsx
export default async function BlogPage() {
  // Esto corre en el servidor — puedes llamar a tu DB directamente
  const posts = await fetch('https://api.example.com/posts', {
    next: { revalidate: 3600 }, // revalidar cada hora
  }).then(r => r.json());

  return <PostList posts={posts} />;
}
```

## Estructura recomendada

Para un proyecto mediano, recomiendo esta organización:

```
src/
  app/           → Rutas y páginas
  components/    → Componentes reutilizables
  lib/           → Utilidades, helpers, config de DB
  types/         → Tipos TypeScript compartidos
```

## Conclusión

El App Router representa un cambio paradigmático en cómo construimos aplicaciones React. El modelo de Server Components reduce el JavaScript enviado al cliente y mejora el performance de forma significativa.

La curva de aprendizaje existe, pero vale la pena: una vez que internalizas cuándo usar Server vs Client Components, el desarrollo se vuelve más predecible y performante.
